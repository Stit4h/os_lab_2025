# Лабораторная работа 4

Сигналы и завершение дочерних процессов, зомби, виртуальная память и POSIX threads.

## Сборка и проверка

```sh
cd lab4/src
make
make test
```

Нужны Linux, GCC, GNU Make, Python 3 и утилита `ps`. `GenerateArray` и
`GetMinMax` используются непосредственно из `../../lab3/src`. Предыдущие
лабораторные не изменяются. Исходный `utils.c` из ЛР3 выдаёт предупреждение
`-Wsign-compare`; размер массива ограничен `INT_MAX`, поэтому индекс `int`
в исходной функции не переполняется на допустимых размерах.

## Задание 1

```sh
./parallel_min_max --seed 42 --array_size 100003 --pnum 4
./parallel_min_max --seed 42 --array_size 100003 --pnum 4 --by_files
./parallel_min_max --seed 42 --array_size 100003 --pnum 4 --timeout 10
```

Без `--timeout` родитель блокируется в `waitpid`. С положительным таймаутом
`alarm` посылает `SIGALRM`, обработчик `sigaction` устанавливает флаг
`sig_atomic_t`, а родитель проверяет дочерние процессы через `WNOHANG`.
Таймер запускается после генерации массива, перед `fork`. При истечении
срока незабранным дочерним процессам посылается `SIGKILL`, затем обязательно
выполняется `waitpid`. Код возврата 124 означает таймаут; неполный ответ
не печатается. Нулевой или отрицательный таймаут отклоняется.

Воспроизводимая проверка таймаута:

```sh
python3 test_lab4.py --timeout-demo
python3 test_lab4.py --timeout-demo --by-files
```

Тест временно собирает библиотеку-перехватчик `fork`, которая останавливает
только дочерние процессы тестируемой программы с помощью `SIGSTOP`.
Исполняемый файл `parallel_min_max` не изменяется. Проверяются сигнал 9,
код 124, сбор статусов, отсутствие оставшихся PID и временных файлов.
Библиотека существует только внутри `TemporaryDirectory`.

## Задание 2

```sh
./zombie 3
```

Ребёнок завершает работу с кодом 42. `waitid` с `WNOWAIT` подтверждает
завершение, сохраняя запись зомби. `ps` показывает `Z` или `Z+`.
Родитель забирает статус через `waitpid`; повторное ожидание даёт `ECHILD`.
Зомби не выполняет код, поэтому `SIGKILL` его не убирает. Нужно забрать
статус; при завершении родителя это делает принявший потомка init/subreaper.
Множество зомби занимает записи таблицы процессов и ограниченный ресурс PID.

## Задания 3 и 4

```sh
./process_memory
nm -n process_memory | grep -E ' (etext|edata|end|cptr|buffer1)$'
```

`etext` — первый адрес после сегмента кода, `edata` — после инициализированных
данных, `end` — после BSS. Это символы линкера, не обычные переменные.
В исходном примере исправлены старый синтаксис C и печать указателей:
используется `%p`, поскольку `%X` обрезает адрес на 64-битной платформе.
Локальные переменные размещены в стеке, `buffer1` — в BSS, `cptr` — в данных,
строковый литерал — в доступной для чтения области, `malloc` выделяет память
динамически. Конкретные адреса могут меняться из-за ASLR.

Общий Makefile собирает `parallel_min_max` и `process_memory`, а также
программы для заданий 2 и 5.

## Задания 5 и 6

```sh
./psum --threads_num 1 --seed 42 --array_size 100003
./psum --threads_num 4 --seed 42 --array_size 100003
```

Массив генерируется один раз до начала измерения. Поток i обрабатывает
полуинтервал `[i*N/T, (i+1)*N/T)`, вычисленный в 64-битной арифметике.
Каждому потоку передаётся `&args[i]`; результат записывается в его собственную
структуру. После `pthread_join` главный поток складывает частичные суммы.
Тип `uint64_t` предотвращает переполнение обычного `int`.

Функции `Sum` и `ThreadSum` вынесены в `sum.c`, интерфейс — в `sum.h`.
Makefile создаёт `libsum.a` и компонует `psum` с `-lsum -pthread`.
`CLOCK_MONOTONIC` измеряет создание потоков, суммирование, ожидание и
объединение результатов; генерация массива в замер не входит.

`make test` проверяет результаты относительно последовательного эталона
`rand` из libc: оба способа IPC, отсутствие и наличие таймаута, массив из

зомби, полные адреса и срабатывание таймаута. Все исполняемые файлы,
объектные файлы и библиотеки исключены из Git через `src/.gitignore`.

